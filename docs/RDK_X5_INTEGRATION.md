# RDK X5 接入与串口协议

记录日期：2026-11-02。维护者确认 RDK X5 已与六足实机联动；以下为源码核查结果，本次未连接串口或执行动作。

## 分工与连接

RDK X5 运行上位控制逻辑；ESP32处理明确命令、运动状态和舵机输出；PCA9685驱动关节。桥接代码检查两个I2C地址 `0x40`、`0x41`。RDK侧实际运行程序尚未在本仓库单独归档，不能把路径工具当该客户端。

当前文本桥读取 ESP32 的 **USB Serial，115200 baud**。一行一条命令，必须发送真实的换行结束符，接收端去除首尾空白。设备名可能表现为 `/dev/ttyUSB*` 或 `/dev/ttyACM*`，仅为示例，必须按实际设备确认。

原有 `Serial2` 是独立的 UART JSON 路径，源码初始化为 GPIO16 RX / GPIO17 TX。不要把USB文本帧与UART JSON帧混用。固件同时输出启动和运行日志，上位机应逐行匹配返回，不能假定每条输入只对应一行输出。

## 命令及真实语义

对应 `firmware/src/main.cpp` 中的 `processRdkCommand()`：

| 命令 | 行为及限制 |
|---|---|
| `PING` | 返回 `PONG`；只证明通信，不证明姿态或舵机正常 |
| `I2C_SCAN` | 返回 `I2C: 0x40=OK/FAIL 0x41=OK/FAIL` |
| `ENABLE_SERVOS` | 检查两个I2C地址，清除旧动作并进入全部腿的测试角度；返回 `SERVOS ENABLED`，**可能产生实际运动** |
| `DISABLE_SERVOS` | 清除动作并关闭PWM输出，返回 `SERVOS DISABLED`；可能失去支撑力，先固定机身 |
| `CALIBRATE` | 输出启用后清偏置并进入测试角度；会改变校准相关状态，不是只读查询 |
| `SERVO <id> <angle>` | ID为 `0..17`，执行校准测试；调试角度不代表实测角度或全部机械可达范围 |
| `STAND` | 清除旧动作并选择 `MOVEMENT_STANDBY`；不是闭环稳定性保证 |
| `SIT` | 当前同样选择 `MOVEMENT_STANDBY`；**没有独立趴下动作** |
| `WALK forward <speed>` | 前进；速度参数约束到 `1..100`，再映射内部速度比例，不是m/s或距离闭环 |
| `WALK backward <speed>` | 后退，速度语义同上 |
| `TURN left` / `TURN right` | 左/右转；没有目标角度或里程计闭环 |
| `STOP` | 清除队列、表演、单腿控制和运动标志；返回 `STOP`，不会切断动力电源 |
| `GET_ANGLES` | 返回 `ANGLES: 0=...` 等软件缓存；不是编码器反馈，行走时也不代表实际关节角度 |

输出关闭时，需要使能的命令返回 `ERR SERVOS DISABLED`。非法行走方向返回 `ERR WALK DIR`；未知命令返回 `UNKNOWN:` 加输入内容。命令存在不代表每项都已完成独立实机验收。

## 操作与反馈边界

启动代码将 `servoOutputEnabled` 置为false并调用关闭PWM的函数；这不是经过认证的硬件安全系统。`ENABLE_SERVOS` 会进入测试角度，不能作无动作握手使用。先用已有串口工具检查 `PING` / `PONG`，运动测试由现场操作者确认零位、支撑、供电和机构范围后进行。

执行器使用与硬件匹配的独立动力电源，按实际原理图核对，不能让RDK的USB接口承担全部舵机动力负载。软件停止不代替物理断电措施。当前不宣称具备已验证的动作watchdog、指令鉴权、编码器反馈或自主避障。AI生成的动作文本不能直接无约束转发。
